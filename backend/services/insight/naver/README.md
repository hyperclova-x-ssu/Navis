## Composition registration

- Construct `createInsightNaver(createNaverTransport({ bindings, fakeOnly }), { now, receiptPath })` inside Insight. Limit bindings by exact operation, method and path in the table. Use the authenticated store identifier for every call. Resolve the linked provider account, Ads record and credential references on the server.
- Route Persona on private `http://naver-virtual:3000` with the PN-P0 workload token, account grant and separate per-operation wire credentials. Supply the pinned clock for test runs and a real clock for hosted runtime. This branch contains no production Compose, gateway, Insight app/index, DB or deployment changes. No new Insight database objects or gateway routes are required.
- Ads authorization uses `searchAdsAuthorization(customerId, keyId, now)`. In the binding's `authorize(request, credential)`, call the returned function with the signature key. Studio uses bearer authorization. Speech uses `X-CLOVASPEECH-API-KEY`. OCR uses `X-OCR-SECRET`. Supply the exact configured OCR path. For live W, require the binding's A6 check before egress and pass trusted approval context through the optional adapter argument.
- In the existing Insight Navis flow, retain `createNavis`'s scoped diagnostics wrapper and bridge endpoint `https://navis-agent.invalid`. Delegate its injected fetch to `studioFetch(activeTurn.scope.storeId, approvalScope)`. Keep A-3 on its existing in-process fixture.
- For the authenticated media handler use `mediaFetch(verifiedStoreId, approvalScope)` at the existing `createMediaService` fetch seam. Retain origin/auth checks, quotas, cancellation and validated media suggestions. Speech results fill editable text. Receipt results fill a reviewed expense candidate. The widget's existing card remains the write entry point.
- B11 uses Financial Center and Studio drafts, B12 uses review and SmartCall statistics, B15 uses review reads and drafts, and B19 uses the owner channel and Ads reports. Preserve each measurement and period as provided. Drafts take their source from the port called. Review reply posting remains on B15's owner-confirmed command.

## Verification

Use the focused Vitest suite and backend typecheck. For the private Compose proof, set `PN_A3_APP` to the staged app tree, `PN_A3_NODE` to a Linux Node 22 binary, `PN_A3_MODULES` to backend dependencies and `PN_A3_PROVIDER` and `PN_A3_CONTRACTS` to the PN-P0/P1–P4 provider and contracts trees. The staged app tree needs real directories for each nested mount. Run `docker compose -f compose.proof.yaml up -d`, `docker compose -f compose.proof.yaml run --rm proof`, then `docker compose -f compose.proof.yaml down --volumes`. The proof uses synthetic credentials, pinned seeds, actual registrar HTTP and PostgreSQL, plus the existing Studio and media clients. Its test-only seed bootstrap calls the capability seed hooks directly to accommodate the Mac snapshot and older gpu-server seed-context exports.
