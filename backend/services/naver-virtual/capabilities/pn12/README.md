# PN-P3 provider handoff

The private Persona NAVER service uses synthetic 안숭잘부 카페 data and assumed account, Place+ and partner approvals. Every route uses PN-P0's workload and account grant. The paths under `/partner-assumed/v1` have Navis-owned contracts. All `ref` values are persona selectors. P/O failure envelopes are generic Navis diagnostics. Cards, additional delete confirmation and outbound approval belong to the existing Navis commands that call these routes.

## PN12 field provenance

| Surface | Owner-visible fields and rules |
| --- | --- |
| Place | A day or week of views, booking and order applications, reviews and SmartCall calls. The SmartCall card uses the same account-scoped PN08 calls and Seoul date boundaries as the SmartCall daily summary. Supported cards carry a signed change percentage only when the comparison period and denominator exist. |
| Blog | Daily and cumulative views for the fixture's owner-authored post. The cumulative card carries the post's own covered period. The report omits unavailable cards. |
| Clip analytics | Seven-day Clip views, profile views and new followers from the creator-owned Clip channel. Blog-linked and MYPLACE-linked clips are outside these observations. |
| Clip publishing | The request has an eligible owner media selector, description, optional creator category, up to five hashtags, and public or private visibility. The simulated share link and receipt lookup are persona acknowledgements. NAVER documents individual Clip URLs and owner-visible private posts. Record the owner-entered link in operation. [Clip URLs](https://help.naver.com/service/30048/contents/24415?lang=ko) · [Owner private content](https://help.naver.com/service/30048/contents/24418?lang=ko) The opaque selector in the HTTP Location header is persona transport metadata. |

## Integration and verification

- Configure Search/Maps provider credentials `keyId` and `key`, Login `clientId` and `clientSecret`, WORKS `readToken` and `writeToken`, and Ads `customerId`, `keyId` and `key` on the corresponding PN-P0 operations. The fixture exposes one eligible media reference. The media bindings for additional owner uploads are adapter handoffs.
- Reuse the existing fixed-clock context for local calls and let deployment seed refresh the synthetic observations using the shared KST clock. Same-generation retries preserve writes. The Navis adapter attaches the official source to the returned report period and staff or media authority comes from its own account grant.
- `pn10/routes.test.ts` asserts field lists and provider-specific errors with Vitest. `verify.mjs` asserts the full private HTTP subset against seeded PostgreSQL in Compose. On the private network it takes the base URL, account ID, marketing workload token, insight workload token, account workload token, customer workload token and fixture instant in that order. Its exported function can exercise one more independently granted account to verify scoped read-back.
- Papago and Voice remain optional selections in PERSONA_NAVER.md §2.2. Live bindings and real calls remain with their respective A6 approval paths. The Clip fallback remains MP4 download, official uploader and owner-entered link where the live partner contract has yet to be verified.

The PN10 Vitest run passed 9 tests and backend `npm run typecheck` exited 0. The isolated Compose project `navis-pnp3-proof-4f926784` imported all four registrars, applied the migrations and seed under the migration role, and exercised the HTTP routes against PostgreSQL using the runtime role. The verifier checked the independent account denial, withheld cards, revocation, distinct publication receipts, duplicate-write results and Clip read-back after a provider restart. The proof project used internal Docker networks and was removed after verification.
