# PN-P2 provider contracts

The private service represents the fictional 안숭잘부 카페 with the approvals and restaurant eligibility defined in the persona design. PN03–PN07 use synthetic records. P/O routes are partner-assumed owner projections. The PN06 chatbot reply and callback events use the selected text-only TalkTalk Chat Bot API V1 schema. [Persona design](../../../../../../03_architecture/PERSONA_NAVER.md)

## Endpoint fields and sources

Paths in the table use `/partner-assumed/v1`. List responses use `items`. Where a list supports paging, `limit` and `offset` are private transport controls. Every `ref` is a private persona selector. P/O errors use HTTP status and generic Navis envelopes. The display-only review thumbnail is never a provider-local marketing asset selector. Adapters must never attribute these diagnostics to NAVER. The corresponding types and source constants are in `backend/packages/naver/contracts/pn03` through `pn07`.

## TalkTalk wire and composition

`POST /chatbot/v1/event` takes the raw provider `Authorization` header and `application/json;charset=UTF-8`. The selected request is `{event:"send",user,textContent:{text}}`. The response is HTTP 200 with `{success,resultCode,resultMessage?}`. The private fixture route `POST /internal/naver-virtual/v1/talktalk/webhook-fixtures/:ref/dispatch` emits the seeded `inbound-01` event when enabled. Accepted replies can emit one settings-enabled echo with `event,echoedEvent,user,partner,textContent`. The wire type allows the example's optional `textContent.inputType` and `options.mobile`. The fixture uses a 1 s local callback deadline. NAVER documents a 3 s connect timeout and 5 s read timeout. An unknown callback result stays unresolved. The effect journal's private `Idempotency-Key` lets Navis retry the same provider attempt without a second reply. [TalkTalk Chat Bot API V1](https://github.com/navertalk/chatbot-api/blob/master/README.md)

The persona process needs `talktalkAuthorization` on each `pn06.chatbot.send` workload grant. Both `pn06.chatbot.send` and `pn06.fixture.dispatch` use the separate private `talktalkCallbackToken` credential for delivery to Marketing. Set `NAVIS_NAVER_VIRTUAL_TALKTALK_CALLBACK_URL` to Marketing's `/internal/v1/naver/talktalk/webhook` and permit that private network direction. Grant `pn06.fixture.dispatch` to proof or fixture automation only. PN-P0 loads the capability registrars, migrations and seeds.

Navis authenticates the owner and revalidates the pressed widget card before submitting a write. The same owner command enforces additional confirmation for deletion, cancellation or early termination. The provider applies operation scope, account scope, state guards and an atomic attempt journal. The PN04 Compose proof attaches the seeded provider-local video `video-cafe-01`. B16 attachments require a provider-local reference bound to the authorized artifact through PN-A2.

## Proof

Run from the repository root with the local tools image and the Compose PostgreSQL 17.11 image already available.

```sh
docker compose --project-name navis-pn-p2-proof --file backend/services/naver-virtual/capabilities/pn03/compose.proof.yaml up --abort-on-container-exit --exit-code-from proof
docker compose --project-name navis-pn-p2-proof --file backend/services/naver-virtual/capabilities/pn03/compose.proof.yaml down --volumes
```

The proof runs live HTTP against a local persona process in the isolated Compose network, with separate PostgreSQL runtime and migration identities and a synthetic Marketing webhook receiver. It asserts exact response keys, scoped authorization and RLS, effect replay after restart, KST seed generations, coupon and promotion lifecycle, callback ambiguity, and quota and attachment policy.
